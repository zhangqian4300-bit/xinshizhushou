# 心石助手交互设计文档

> 版本：MVP v1.0
> 日期：2026-03-28
> 核心原则：Agent拥有最大权限优化用户体验

---

## 一、核心设计理念

### 1.1 Agent权限边界

传统产品设计中，UI样式、内容结构、交互流程都是预先定义的，AI只负责生成文字内容。

**心石助手打破这个边界**：

```
┌─────────────────────────────────────────────────────────────┐
│  传统模式                                                    │
│  ┌─────────────┐                                            │
│  │  固定UI模板 │ ← 预先设计好的样式、布局、组件              │
│  └─────────────┘                                            │
│        ↓                                                    │
│  ┌─────────────┐                                            │
│  │   AI填充    │ ← AI只负责填充文字内容                      │
│  └─────────────┘                                            │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  心石助手模式                                                │
│  ┌─────────────┐                                            │
│  │  最小容器   │ ← 只提供最基础的渲染能力                     │
│  └─────────────┘                                            │
│        ↓                                                    │
│  ┌─────────────────────────────────────────────────────────┐│
│  │  Agent全权设计                                          ││
│  │  ├── 内容：说什么、怎么说                               ││
│  │  ├── 样式：用什么颜色、什么布局                          ││
│  │  ├── 结构：分几个模块、用什么组件                        ││
│  │  └── 交互：需要用户做什么、怎么引导                      ││
│  └─────────────────────────────────────────────────────────┘│
└─────────────────────────────────────────────────────────────┘
```

### 1.2 Agent权限清单

| 权限维度 | Agent可以做什么 | 传统AI能做什么 |
|----------|-----------------|----------------|
| **内容** | 完全自定义文字、语气、结构 | 填充固定模板 |
| **样式** | 定义颜色、间距、图标、动画 | 无权限 |
| **组件** | 选择用什么UI组件（卡片、列表、按钮等） | 无权限 |
| **交互** | 定义用户下一步可做什么（按钮、链接） | 无权限 |
| **时机** | 决定什么时候推送、什么时候追问 | 无权限 |
| **记忆** | 调用用户历史数据决定展示什么 | 无权限 |

### 1.3 设计原则

1. **最小容器原则**：前端只提供渲染能力，不预设UI模板
2. **对话驱动原则**：所有个性化内容都源于对话，不是预设规则
3. **Agent主导原则**：AI决定"呈现什么"和"怎么呈现"
4. **渐进引导原则**：Agent根据用户状态决定交互深度

## 二、动态UI生成机制

### 2.1 响应格式定义

Agent的响应不再只是纯文本，而是**结构化的UI指令**：

```typescript
// Agent响应格式
interface AgentResponse {
  // 内容层
  content: {
    text: string;              // 主文本内容
    tone: 'warm' | 'direct' | 'gentle';  // 语气风格
    sections?: Section[];      // 内容分段（可选）
  };

  // 样式层（Agent自定义）
  style: {
    theme: 'calm' | 'energetic' | 'reflective';  // 情绪主题
    colors?: {
      primary?: string;        // 主色调
      background?: string;     // 背景色
      accent?: string;         // 强调色
    };
    layout: 'card' | 'list' | 'conversation' | 'timeline';  // 布局类型
    animation?: 'fade' | 'slide' | 'none';  // 动画效果
  };

  // 组件层（Agent选择）
  components: Component[];

  // 交互层（Agent定义）
  interactions: {
    buttons?: Button[];
    suggestions?: string[];    // 建议用户说的话
    nextAction?: NextAction;   // 下一步引导
  };

  // 记忆层（Agent调用）
  memoryContext: {
    referencedHistory?: string[];  // 引用了哪些历史对话
    userProfileUsed?: boolean;     // 是否使用了用户画像
    stateChange?: StateChange;     // 用户状态变化记录
  };
}

// 组件类型
interface Component {
  type: 'text' | 'card' | 'button' | 'progress' | 'timeline' | 'quote' | 'action-list';
  content: any;
  style?: any;
  action?: any;
}
```

## 三、对话驱动的个性化计划

### 3.1 传统模式 vs Agent模式

**传统模式**：
```
测评结果 → 固定规则 → 固定任务列表

焦虑纠结型 → 五减法默念（固定）
高压心疲型 → 每天15分钟独处（固定）
```

**Agent模式**：
```
对话内容 → Agent分析 → 动态生成计划

用户说「我每天加班到10点，根本没时间独处」
→ Agent理解：高压心疲型，但时间有限
→ 生成：把15分钟拆成「通勤路上发呆5分钟 + 睡前关手机10分钟」

用户说「我不喜欢写东西，写字让我更烦」
→ Agent理解：焦虑纠结型，但写字会增加负担
→ 生成：改成「在心里默念三遍，然后把纠结的事说出来」
```

### 3.2 Agent生成计划的逻辑

Agent生成计划时，会调用以下信息：

```typescript
interface PlanGenerationContext {
  // 用户画像
  userProfile: {
    exhaustType: string;       // 内耗类型
    assessResult: any;         // 测评详情
    preferences?: string[];    // 用户偏好（从对话中提取）
    constraints?: string[];    // 用户约束（时间、习惯等）
  };

  // 对话历史
  recentConversations: {
    date: string;
    content: string;
    extractedInsights: string[];  // Agent从对话中提取的洞察
  }[];

  // 状态变化
  progressState: {
    stonesCleared: number;     // 已清理的石头数
    recentImprovement?: string; // 近期进步
    currentFocus?: string;     // 当前聚焦的问题
  };
}
```

## 六、前端渲染层设计

### 6.1 最小渲染容器

前端不预设UI模板，只提供渲染能力：

```typescript
// 前端渲染器
class AgentResponseRenderer {
  // 渲染Agent响应
  render(response: AgentResponse): VNode {
    const { content, style, components, interactions } = response;

    // 1. 应用样式
    const themeStyle = this.applyTheme(style);

    // 2. 渲染组件
    const componentNodes = components.map(c => this.renderComponent(c));

    // 3. 渲染交互
    const interactionNodes = this.renderInteractions(interactions);

    // 4. 组合
    return this.compose(themeStyle, componentNodes, interactionNodes);
  }

  // 组件渲染器（支持Agent选择的组件类型）
  renderComponent(component: Component): VNode {
    switch (component.type) {
      case 'text': return this.renderText(component);
      case 'card': return this.renderCard(component);
      case 'button': return this.renderButton(component);
      case 'progress': return this.renderProgress(component);
      case 'timeline': return this.renderTimeline(component);
      case 'quote': return this.renderQuote(component);
      case 'action-list': return this.renderActionList(component);
      case 'guided-steps': return this.renderGuidedSteps(component);
      case 'celebration': return this.renderCelebration(component);
      default: return this.renderText(component); // fallback
    }
  }
}
```

### 6.2 支持的组件类型

| 组件类型 | 用途 | Agent可配置项 |
|----------|------|---------------|
| `text` | 纯文本 | 内容、语气标记 |
| `card` | 卡片容器 | 内容、边框、阴影 |
| `button` | 按钮 | 文字、动作、样式 |
| `progress` | 进度条 | 当前进度、总量、标签 |
| `timeline` | 时间线 | 事件列表、状态标记 |
| `quote` | 引用语 | 内容、作者、位置 |
| `action-list` | 任务列表 | 任务内容、难度、时间 |
| `guided-steps` | 分步引导 | 步骤内容、当前步 |
| `celebration` | 庆祝卡片 | 内容、动画效果 |

## 八、总结

### 8.1 设计理念对比

| 维度 | 传统产品设计 | 心石助手设计 |
|------|--------------|--------------|
| UI定义 | 预设模板 | Agent动态生成 |
| 内容生成 | AI填充固定位置 | Agent全权定义 |
| 个性化 | 规则匹配 | 对话驱动 |
| 交互引导 | 固定流程 | Agent自主判断 |
| 记忆运用 | 无 | Agent主动引用 |

### 8.2 Agent权限边界

Agent拥有最大权限优化用户体验，但需遵守：

1. **减法理念约束**：不增加用户负担，每次只给1-2个动作
2. **安全边界约束**：不做医学诊断，不推荐药物
3. **语气约束**：温和直白，不用专业术语

### 8.3 实现路径

1. **Phase 1**：实现基础渲染容器，Agent生成简单响应
2. **Phase 2**：Agent生成复杂组件（timeline、action-list）
3. **Phase 3**：Agent主动引导（触发条件判断）
4. **Phase 4**：Agent定义动画和复杂交互
